# 打卡体系映射 v2

## 一、原则

现有16周打卡不推倒重来，不把已完成学习或代码工作作废；只把任务重新映射到最终双轴架构。打卡记录与科学结论、导师签核分开。

## 二、原技能到新战略

| 原打卡/技能 | 新战略用途 | 不应再承担 |
|---|---|---|
| RDKit结构处理 | FASN_activity_master、天然产物身份、Murcko/ECFP/AD | 自动证明来源或活性 |
| ChEMBL API | FASN assay provenance、relation/censor和模型集 | 直接拼接成统一活性标签 |
| RF/XGBoost | FASN baseline和严格split | 随机高分即候选放行 |
| GNN | 仅在FASN GNN启用门控满足后 | 为满足题目硬做 |
| 适用域/不确定性 | FASN天然产物拒判和模型可信度 | 用一个相似度阈值替代验证 |
| Docking/DockScope | 结构解释、姿态可视化、已知共晶关系 | 活性排序、选择性或机制证明 |
| 文献证据审计 | Moracin N机制重定位、临床管线和安全边界 | 把未命中写成全世界没有 |
| 实验设计/统计 | Moracin N Gate0–3；未来FASN酶实验 | 先采购再追问科学问题 |
| 版本控制/哈希 | raw/master/model/reports可复现 | 覆盖旧失败结果 |

## 三、16周建议映射

### 第1–4周：数据和证据

- 熟悉FASN_activity_master字段；
- 人工复核随机抽样的activity/assay/document；
- 读Moracin N、MASH ferroptosis、denifanstat原始文献；
- 完成供应商、COA和Gate 0材料准备。

### 第5–8周：建模和方法审计

- 复现mean/descriptor/RF/XGBoost；
- 复现scaffold split和UQ；
- 建立FASN外部验证候选；
- 不运行GNN，除非门控明确通过。

### 第9–12周：双轴验证

- Moracin N完成Gate 1/2/3或记录停止信号；
- FASN完成assay-family复核和Tier 2纳入规则；
- 需要时做THRβ现成reporter最小裁决。

### 第13–16周：结果和论文

- 按真实结果锁定主张；
- 保存阴性、未完成和材料失败；
- 形成FASN方法稿或Moracin N机制稿的初稿；
- 由导师决定是否进入后续实验/投稿。

## 四、成员分工建议

- 数据组：FASN provenance、去重、relation/censor和来源记录；
- 算法组：baseline、scaffold/time、UQ、AD和模型卡；
- 文献组：Moracin N、MASH ferroptosis、临床管线和监管来源；
- 实验组：Gate0–3、材料、对照和统计预注册；
- 汇总组：版本、哈希、图表、标题和导师审批包。

## 五、打卡纪律

- 代码跑通不等于科学结论完成；
- 阅读完成不等于导师采信；
- 未完成不等于阴性；
- 不能为了打卡数量补充无科学问题的候选或GNN；
- 每周记录路径、版本、输入、输出和待人工复核项。
